# Chat Transcript V1

Status: implemented on `feat/chat-transcript` (Issue #74). Copy or download one conversation’s readable dialogue from the existing thread `···` menu.

## Goal

Let a signed-in owner copy a clean plain-text transcript or download UTF-8 Markdown for a single conversation—without a new page, toolbar, share link, or account-export change.

## Architecture

```text
Sidebar ··· menu
  → Copy transcript  → GET /api/conversations/:id/transcript?format=plain → clipboard
  → Download (.md)   → GET /api/conversations/:id/transcript?format=markdown&download=1 → file
         │
         ▼
createSupabaseServerClient + getAuthenticatedUser
  → conversations by id + user_id (active or archived)
  → messages paged (TRANSCRIPT_PAGE_SIZE) ordered by position, id
  → sanitize assistant text; omit streaming/error rows
  → format plain (Markdown stripped) or Markdown (roles + timestamps)
```

| Piece | Role |
| --- | --- |
| `lib/chat/transcript.ts` | Turn selection, plain/Markdown formatting, filename, size caps |
| `app/api/conversations/[id]/transcript/route.ts` | Auth, origin, owner filter, paging, response headers |
| `components/chat-sidebar.tsx` | Menu entries |
| `components/chat-workspace.tsx` | Fetch / preview build, clipboard, blob download, notices |

Local preview builds the same formats from mock conversation messages (no API).

## Transcript contents

- Title header, chronological user/assistant turns, role labels, ISO timestamps.
- Interrupted assistant turns keep a “Stopped” note.
- Assistant text passes through `sanitizeModelOutput` (hidden reasoning removed).
- Streaming placeholders and error rows are omitted (not shown as completed replies).
- No system/developer prompts, provider secrets, context diagnostics, or attachment binaries.
- Unicode, code fences, lists, tables, and citation markers are preserved in `.md`; Copy strips Markdown syntax via `markdownToClipboard().plain`.

## Limits

- Message page size: 200 (`TRANSCRIPT_PAGE_SIZE`).
- Max messages: 5,000; max characters: ~2 MiB — oversized requests return 413 with a clear error (no silent truncation).

## Security

- Cookie session only; rejects `user_id` / `userId` / `user` query params.
- Origin mismatch → 403; missing conversation or other owner → opaque 404.
- Explicit `.eq("user_id", …)` plus RLS; `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.
- Safe download filename (no path separators); no public unlisted URLs; no migrations or new env vars.

## Out of scope

Account JSON export changes, share links, toolbars, microphone/speech transcripts, attachment file bytes, migrations.
