# Conversation Instructions V1

## Status

Implemented on branch `feat/chat-roles-custom-instructions` (simplifies issue [#66](https://github.com/habiibullahm/nibie-code/issues/66)). Requires additive migration `0025_conversation_instructions.sql` on shared Preview/production DBs (approval gate / `allow-shared-db-migrate` when intentional).

## Goal

Let users save persistent, per-conversation guidance for how Nibie should respond — without cluttering the composer or introducing role presets.

Users can still type `Act as…` in any message. Saved instructions are optional soft guidance for that thread only.

## UX

- Conversation `···` menu → **Chat instructions**
- Minimal dialog: title, short description, multiline textarea (≤ 2,000 characters), Cancel / Save instructions, clear by saving empty
- Optional sidebar badge with tooltip `Custom instructions active`
- Composer stays Room / Model / Research only

## Trust boundary

| Layer | Authority |
| --- | --- |
| Server context-policy / security | Highest |
| Current user request | Overrides soft guidance |
| Conversation instructions | Soft, untrusted |
| Room guidance | Soft, untrusted |
| Account profile | Soft, untrusted |

Instructions never authorize Actions, change RLS, or impersonate tool results.

## Persistence

Additive column on `conversations`:

- `custom_instructions` nullable text (1–2000 trimmed, or null)

Owner-only via existing conversations RLS. Server action: `updateConversationInstructionsAction`. Configure after the conversation exists (after first message). Stream route never accepts client `system` / `developer` arrays for instructions.

## Context wiring

- Render: `lib/chat-instructions/context.ts` → untrusted `instructions` block in `buildContext`
- Empty / null → **zero** extra provider content

## Export

Account export includes `customInstructions` when the column is present.

## Out of scope

Role presets, composer role picker, prompt marketplace, executable tools from instructions, cross-thread sharing.
