# Web Search V1

Status: implemented on `feat/web-search-v1`. Optional server-side grounding for current public facts. Not a browser agent. Chat continues when web is unset or fails.

## Goal

Give Nibie access to current external information (versions, news, leadership, public docs) without crawlers, login scraping, or agent loops. Capability routing is deterministic. Room hybrid retrieval and web search compose independently.

## Architecture

```text
User message (saved)
  → Room hybrid retrieval (existing; independent)
  → decideWebSearch(query, { hasRoomFileContext })
  → if search && configured:
        searchWeb → select → fetchWebPage (SSRF) ×N → extract
        → WebContextInput[] (untrusted, provenance)
     else: no web / degraded empty
  → buildContext({ …, web })
  → toProviderMessages → chatProvider.stream
```

| Module | Role |
| --- | --- |
| `lib/web/routing.ts` | Deterministic `decideWebSearch` + `WEB_SEARCH_RULES` |
| `lib/web/config.ts` | Env → `WebSearchConfig \| null` (fail soft) |
| `lib/web/provider.ts` + `providers/tavily.ts` | `searchWeb` adapter (Tavily V1) |
| `lib/web/ssrf.ts` / `fetch-page.ts` | URL/DNS guards + bounded HTTP(S) GET |
| `lib/web/extract.ts` / `select.ts` | Readable text + result/page/source caps |
| `lib/web/pipeline.ts` / `degrade.ts` | Orchestration; never throws to the route |
| `lib/context/web-context.ts` | Untrusted fences + provenance headers |
| `app/api/chat/route.ts` | After Room files, before `buildContext`; logs only |

Web search is orthogonal to Fast / Balanced / High model routing.

## Environment variables

Server-only. Never `NEXT_PUBLIC_*`. When unset or invalid, web is disabled and chat continues.

| Variable | Purpose | Default |
| --- | --- | --- |
| `WEB_SEARCH_PROVIDER` | Provider id (`tavily` only in V1) | — (required with key) |
| `TAVILY_API_KEY` | Tavily API key | — |
| `WEB_SEARCH_MAX_RESULTS` | Search hit cap (clamped 5–8 in select) | `8` |
| `WEB_FETCH_MAX_PAGES` | Pages to fetch (clamped 2–4) | `4` |
| `WEB_CONTEXT_MAX_SOURCES` | Final sources to the model (≤5) | `5` |

## Capability routing

Pure regex/keyword heuristics — no extra LLM. Empty/whitespace → no search. First matching search rule wins; otherwise a no-search reason.

**Search when:** explicit web/search request; temporal currency (latest / current / today / …); news; strong prices/markets cues (stock, crypto, bitcoin, …); schedules; strong release cues (changelog, what’s new in, CVE); public figures/leadership; current docs; strong jobs cues (hiring, job posting, open roles); stale public-info patterns **with** a currency cue; Indonesian / IDX market topic cues (IHSG, saham, …) **with** condition/direction intent (kondisi, arah, analisa, anjlok, …) even without a separate freshness word. Bare weak tokens (`version`, `release`, `price`, `job`, bare IHSG) search only when a currency cue is also present, and only after conceptual/coding/writing suppressors.

**Do not search:** conceptual explain/teach (without currency) such as “apa itu IHSG?”; pure writing/rewrite; generic coding without currency/docs cues; weak-token conceptual/coding false positives (version control, “fix the version check”, consulting pricing, release trains, job queues); bare market-topic mentions without condition or currency; Room-grounded asks (`based on this file`, `in this room`, …) when `hasRoomFileContext` is true — unless the user explicitly asks to search the web.

Logged as `web.route.decided` with `{ search, reason }` only — never the query text.

## SSRF and fetch bounds

Every outbound page URL (including each redirect hop) is validated:

- **Allow:** `http:` / `https:` only
- **Deny:** `file:`, `ftp:`, `data:`, `javascript:`, credentials-in-URL, localhost / `127/8` / `::1`, RFC1918, link-local, ULA, CGNAT, cloud metadata hosts, `.local` / `.internal` suffixes
- **DNS rebinding:** resolve hostname; reject if any address is blocked; re-validate on redirects (max 3). V1 does **not** pin the TCP connect to the pre-checked addresses (DNS TOCTOU / rebinding between check and connect remains a known limit).
- **Transport:** ~8s page timeout, 512 KiB body cap, content-type allowlist (`text/html`, `text/plain`, `application/xhtml+xml`), fixed Nibie UA
- **Extract:** strip script/style/nav/footer; cap ~20k chars per page; no headless browser

Search results: 5–8. Pages fetched: 2–4. Final web sources: ≤5. Token budget: `WEB_TOKEN_CAP = 1200`.

## Provenance and untrusted context

Each source is a `WebContextInput`: `url`, `title`, `domain`, `retrieval` (`web_search` \| `web_snippet_only`), optional `publishedAt`, `text`.

Rendered inside `<untrusted_web_content>` with provenance headers. Boundary-tag injections in body text are stripped. Prefaced so web data cannot override product/Room/user rules. **Never invent sources** — if the pipeline is empty, the web block is omitted. When routing wanted search but sources are empty (unconfigured, provider fail, empty pipeline), product policy gains an authoritative “Web verification was unavailable…” instruction, and the context panel shows Web sources as not used for that soft reason.

Context order: product policy → profile → Room → pins → Room files → attachments → **web** → thread summary → dialogue → current user message last.

Diagnostics: `{ type: "web", label: "Web sources", … }` after file/attachment.

## Room + web

Room hybrid retrieval and web run independently:

- Room failure does not block web; web failure does not block Room.
- Room-only grounding (`room_sufficient`) skips web when file context is present.
- Currency / news / explicit-search asks still search even when Room files are present; both file excerpts and web blocks can appear in one plan (files before web).

## Degradation

| Failure | Behavior |
| --- | --- |
| Unconfigured provider/key | No web block; chat continues; authoritative verification-unavailable instruction + soft Web sources diagnostic |
| Route says no | No web I/O |
| Search error / timeout | Empty sources; chat continues; `web.search.failed`; verification-unavailable instruction |
| Search OK, fetches fail | Snippet-only sources when available |
| Partial fetches | Successful pages + snippet fill, ≤5 |
| Pipeline throw (defensive) | Caught in route; empty web + verification-unavailable instruction |

Observability events use counts, categories, latency, and route reason — never keys, full HTML, query dumps, or auth headers.

## Eval coverage

Fixture-backed unit suite: `tests/fixtures/web-search.ts` + `tests/unit/web-search-eval.test.ts`.

| Case | Asserts |
| --- | --- |
| No web | Conceptual / writing / coding → `search: false`; provider not called |
| No web (weak tokens) | Version-control / pricing / release-train / job-queue style asks → `search: false` |
| Current version | Currency + version/release query → search; mocked pipeline yields sources |
| News | News query → search + sources |
| CEO | Leadership query → search + sources |
| Explicit search | “search the web…” → search + sources |
| Room only | File-grounded ask + file context → `room_sufficient`; no web block |
| Room + web | Room files + currency ask → file + web in plan (files before web) |
| Prompt injection | Hostile HTML/text stays untrusted; policy block unchanged; fence intact |
| SSRF localhost | Loopback, metadata, private, `file://` → `SsrfError`; no DNS connect |
| Provider failure / empty web | Search throw or empty sources → degraded; verification-unavailable instruction; chat still builds |

## Out of scope

Browser agents/automation, login scraping, CAPTCHA, forms, purchases, agent loops, crawling, web index DB, vectorizing the public web, scheduled monitoring, connectors, image search, OCR, multi-query LLM rewrite, LLM reranking, production merge/deploy as part of this stream. Citations UI is Citations V1. Explicit Deep Research V1 is a separate capability that reuses this search/fetch stack with its own budgets (`docs/feature/deep-research/v1.md`).

## Known limitations

- HTML extraction without a browser is imperfect; snippet fallback covers many fetch/extract failures.
- Routing is conservative keyword/heuristic — edge phrasings may under- or over-trigger.
- DNS check vs connect is not address-pinned: a rebinding host could change A/AAAA records between SSRF validation and the outbound connect (V1 TOCTOU limit).
- Live Tavily accuracy, latency, and ranking are not proven by the fixture eval; preview smoke needs `TAVILY_API_KEY`.
- Citations V1 (`docs/feature/citations/v1.md`) adds claim↔source markers and a Sources list on top of these web inputs.
- Web adds search + fetch latency on the critical path when routing says search and the provider is configured.
