# Deep Research V1

Status: implemented on `feat/deep-research-v1` (depends on Citations V1). Explicit, bounded multi-source research — not normal web search, not an autonomous browser agent.

## Goal

User opts into Deep Research for a question. Nibie plans bounded queries, searches, fetches strongest pages (SSRF-safe), extracts evidence, optionally runs one follow-up round, then synthesizes a cited answer using Citations V1.

## Control

Composer **Research** menu: **Normal** vs **Deep Research**. Orthogonal to Fast / Balanced / High. Never auto-triggered on broad questions.

## Orchestrator

```text
normalize → plan → bounded queries → search → fetch strongest → dedupe
  → extract evidence → gap detection → optional ONE follow-up → synthesize (cited)
```

Budgets (starting): subquestions ≤5, initial queries ≤8, follow-up queries ≤4, results/query 5, candidate URLs ≤30, fetched pages ≤12, final cited ≤10. Max rounds: initial + 1 follow-up (`RESEARCH_MAX_ROUNDS`).

Wall-clock: gather (plan+search+fetch) ≤70s; synthesis ≤90s and capped by remaining of a 165s route budget (under `maxDuration` 180). When `timeSensitive`, prefer fresher `publishedAt`; when the question asks for official/docs, prefer primary/docs-like sources.

Empty collection after gather is a **hard failure** (transparent error, no credit reservation, no synthesis). Partial evidence may synthesize as `incomplete` with an honest notice and UI label.

## Citations

Reuses Citations V1 `SourceReference` pipeline (`attachWebCitationHandles` with research max 10). Same handles, stream filter, `message_sources`, UI markers/Sources. No second citation system.

## UX / Stop / persistence

- Progress stages only: Planning / Searching / Reading / Synthesizing (SSE `progress`; no CoT).
- Stop cancels outstanding work and marks interrupted (existing Stop patterns).
- Persists final answer + citations; high-level run metadata in `message_research` (counts/status/usage policy — no hidden CoT).
- UI surfaces Deep Research · Incomplete / · Failed from persisted research status.

## Usage

Temporary policy `temporary_undercount_v1`: charges the selected mode once for synthesis when sources were gathered. Empty collection does **not** reserve or charge. Planner/follow-up model calls and multi-query search/fetch are **not** separately metered yet — undercount is explicit in logs (`researchUsagePolicy`) and docs. Observability reports model/search/page counts + duration.

## Security

All page fetches go through existing `fetchWebPage` / SSRF. No second unsafe fetch path.

## Out of scope

Autonomous agents, browser click automation, login, recursive crawl, unlimited loops, background/scheduled research, connectors, code exec, shopping, auto-Deep-Research, CoT UI, knowledge graph.

## Observability (safe fields only)

`research.started` · `research.plan.completed` · `research.search.completed` · `research.fetch.completed` · `research.followup.started` · `research.synthesis.started` · `research.completed` · `research.interrupted` · `research.failed`
