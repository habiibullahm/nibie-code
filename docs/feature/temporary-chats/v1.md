# Temporary chats V1

A temporary chat is a conversation the user starts with the ghost **Temporary chat** button next to New chat, before the
first message. It is for one-off questions that should leave nothing behind.

## Behavior

- **Not in history.** It never appears in the sidebar, the archive, chat search, last-chat restore, or another chat's
  historical lookup ("What did we decide about…").
- **No Memory, summaries or past chats.** The chat route does not run explicit remember/forget, does not retrieve saved
  memories, does not read or write a rolling thread summary, and skips historical lookup. On every turn the model gets a
  standing instruction (`TEMPORARY_CHAT_INSTRUCTION`) so it says plainly that nothing was saved or recalled.
  Settings personalization (preferred name, response length, custom instructions) still applies; it is account settings,
  not Memory.
- **General only, no attachments.** It cannot start in or move into a Room, and the server ignores a Room on it. Files
  cannot be attached, because attachment bytes live in Storage, which the conversation cascade does not reach.
- **Deleted when left.** Leaving it in the app (another chat, a Room, New chat, or turning the toggle off) deletes the
  conversation through `discardTemporaryConversationAction`, which only deletes rows with `temporary_expires_at` set.
  Messages, attachments, action runs, sources and usage reservations go with it through the existing cascade.
  Reloading the page keeps it.
- **Expiry.** `conversations.temporary_expires_at` is set to 24 hours after the chat starts. An expired chat is treated
  as deleted everywhere (workspace read, chat route) even before cleanup runs. Cleanup happens in two places:
  starting a new temporary chat deletes the owner's expired ones, and `/api/cron/purge-temporary-chats` (GET or POST)
  (Bearer `CRON_SECRET`, service-role key) deletes every expired one. `vercel.json` runs it once a day at 03:15 UTC
  (Vercel Cron sends `Authorization: Bearer $CRON_SECRET`; daily is the most frequent schedule every Vercel plan allows),
  so an abandoned chat is gone at most about 48 hours after it started.

Usage is charged as for any reply: weekly credits and spend are counted when reserved, so deleting a temporary chat never
refunds usage.

## Schema

Migration `0029_temporary_conversations.sql` is additive: one nullable column and a partial index on it. Until it is
applied, reads fall back to the ordinary columns (no temporary chats can exist), and starting a temporary chat returns
"Temporary chats aren't available yet." It never falls back to creating an ordinary chat.

## Rollout notes

- Preview and Production share one database. Apply 0029 only through the reviewed migration process.
- The daily cleanup needs `CRON_SECRET` and `SUPABASE_SERVICE_ROLE_KEY` in the Production environment; without them the
  route answers 503 and expired chats stay (hidden) until their owner starts another temporary chat.
- Workbench (behind `WORKBENCH_UI_ENABLED`) hides "Edit in Workbench" in a temporary chat, and
  `createWorkbenchFromAssistantAction` refuses one, since a Workbench document outlives its chat.
