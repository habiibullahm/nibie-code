# Chat Roles & Custom Instructions V1

## Status

Implemented on branch `feat/chat-roles-custom-instructions` (issue [#66](https://github.com/habiibullahm/nibie-code/issues/66)). Requires additive migration `0026_chat_roles.sql` on shared Preview/production DBs (approval gate / `allow-shared-db-migrate` when intentional).

## Goal

Give each conversation an explicit, persistent **Chat role** and optional **Custom instructions** so users can keep distinct working modes without repeating setup each turn.

This is **not** permission to edit Nibie's server-owned system policy. Custom text is user-owned, lower-trust soft guidance.

## UX

- Composer **Role** menu: General (default), Developer, Researcher, Writer, Product Lead, Custom.
- Lightweight **Chat instructions** editor (advanced) with ≤ 2,000 characters.
- Disclaimer: “These instructions guide Nibie's replies. They do not override safety rules or authorize tools.”
- Changing role/instructions affects the **next** response only; settings persist per conversation and stay isolated across threads.
- In a Room, room context still applies; chat role is thread-scoped.

## Trust boundary

| Layer | Authority |
| --- | --- |
| Server `context-policy` / security | Highest |
| Current user request | Overrides soft guidance |
| Chat role + custom instructions | Soft, untrusted |
| Room guidance | Soft, untrusted |
| Account profile | Soft, untrusted |
| Saved / retrieved context | Soft, untrusted |

Neither chat role nor Room may authorize Actions, change RLS, or impersonate tool results.

## Persistence

Additive columns on `conversations`:

- `chat_role` enum (`general` default)
- `custom_instructions` nullable text (1–2000 trimmed)

Owner-only via existing conversations RLS. Server action: `updateConversationRoleAction`. Stream route never accepts client `system` / `developer` message arrays.

## Context wiring

- Registry: `lib/chat-roles/registry.ts` (`chat-role-registry-v1`)
- Render: `lib/chat-roles/context.ts` → untrusted `chat_role` block in `buildContext`
- Provider fold: second data system message via `toProviderMessages` (with room/profile/…)
- General + empty custom → **zero** extra provider content

## Export

Account export includes `chatRole` and `customInstructions` when columns are present.

## Out of scope (V1)

Generalized agent framework, prompt marketplace, arbitrary tool messages, user-supplied executable tools, custom model parameters, cross-thread prompt sharing, opaque role-based provider switching.
