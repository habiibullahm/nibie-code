# Actions / Tools V1

Status: implemented. Server-owned Action Runtime with read-only Actions (`web.search` plus GitHub Read). Not agents, not multi-tool loops, not connectors. GitHub Read chat wiring: [github-read-v1.md](./github-read-v1.md).

## Goal

Give Nibie a bounded, auditable path to **do one allowlisted thing** and feed a structured result into chat synthesis — without autonomous agents or model-supplied handlers.

## Architecture

```text
User message
  → Deep Research? (explicit) → research Cost Guard path
  → decideGitHubRead (deterministic) → one github.* Action → Cost Guard Action stream → “Used GitHub”
  → else decideWebSearch → web.search Action → Cost Guard Action stream → “Used Web Search”
  → else Fast path (no Action)
```

| Module | Role |
| --- | --- |
| `lib/actions/types.ts` | ActionDefinition, capabilities, ActionResult, run statuses |
| `lib/actions/registry.ts` | Allowlist only; reject unknown IDs |
| `lib/actions/permissions.ts` | V1 enables `read`; mutations require future confirmation |
| `lib/actions/runtime.ts` | Validate → permission → execute (max 1 / generation) → audit |
| `lib/actions/tools/web-search.ts` | Wraps `lib/web` pipeline (SSRF, bounds, degrade) |
| `lib/actions/tools/github-*.ts` + `lib/github/*` | GitHub Read (public-only client, tools, `decideGitHubRead`) |
| `lib/actions/auto-web-response.ts` | Shared Action SSE + Cost Guard path for `web.search` and `github.*` |
| `drizzle/0019_action_runs.sql` | Owner-scoped audit table + RLS |
| `drizzle/0020_action_runs_insert_checks.sql` | Tighter INSERT ownership checks |
| `drizzle/0021`–`0023` | Append-only server writes; `0023` revokes audit RPC EXECUTE from `authenticated` and grants `service_role` only |
| `lib/supabase/service-role.ts` | Server-only Action audit client (`SUPABASE_SERVICE_ROLE_KEY`) |
| Preview App DB Migration | Applies additive `action_runs` migrations to the shared DB only after `allow-shared-db-migrate` / `workflow_dispatch` |

## First Action: `web.search`

- Capability: `read`
- Input: `{ query }` (Zod)
- Output items: title / url / snippet / provenance
- Automatic Web Search routing is preserved — when routing says search, the Action path runs instead of calling the pipeline ad hoc
- Citations V1 and Deep Research are unchanged (Deep Research does not go through Actions V1)

## Lifecycle & UI

`requested → running → completed | failed | cancelled` (`waiting_for_confirmation` reserved for later mutations).

Minimal UX: “Searching the web…” / “Used Web Search”, or “Checking GitHub…” / “Used GitHub”. No agent dashboard.

## Safety

- Model cannot supply code, handler names, credentials, or permissions
- Stop → AbortSignal through runtime; cancelled is truthful; no further Actions after cancel
- Action / web bodies remain untrusted; failure injects an authoritative “do not claim you searched” instruction
- `action_runs.input_summary` is sanitized (no secrets/tokens/cookies)
- Browser/`authenticated` clients cannot call `insert_action_run` / `complete_action_run`; Action Runtime writes via the service-role audit client with explicit owner `p_user_id`

## Persistence

Completed `web.search` / `github.*` runs are hydrated from `action_runs` in `getChatWorkspaceData` so “Used Web Search” / “Used GitHub” survive stream settle and reload (same pattern as `message_research`).

Action turns emit an early `start` (for live Action status), then a follow-up `context` SSE event with diagnostics after `buildContext`, restoring the context sources panel.

## Tracked debt (S1)

`lib/actions/auto-web-response.ts` still duplicates much of the normal chat SSE / reservation / citation / stop loop from `app/api/chat/route.ts`. Further extraction remains desirable, but web + GitHub now share one Action stream helper.

## Out of scope

Agents, multi-tool loops, computer-use, code exec, Gmail/Calendar/Drive mutations, GitHub mutations, private GitHub OAuth, Connectors dashboard, MCP marketplace, workflow builder, scheduled Actions, WRITE tools (`pin.create`, etc.).
