# Nibie Settings V1

## Status

Implemented. This file is the original Settings V1 spec. The release checklist is [docs/product/V1_RELEASE.md](../../product/V1_RELEASE.md). Account deletion is still unavailable.

## Goal

Add a lightweight Settings experience to Nibie for user preferences,
chat behavior, personalization, and data controls without duplicating
existing conversation-level controls.

The Settings feature should improve product maturity while keeping
Nibie's chat experience simple and fast.

## Current Product Baseline

Already exists:

### Appearance
- Dark / Light / System
- Dark is default
- stored per device
- controlled from sidebar account footer

### Model
- Fast / Balanced / Reasoning
- per-conversation
- only configured server-side modes are exposed
- persisted in `conversations.selected_model`

### Reasoning
- Auto / Low / Medium / High
- device preference
- capability-gated by server configuration
- hidden when unsupported

### Chat behavior
- Enter sends
- Shift+Enter inserts newline
- auto-follow while near bottom
- no message timestamps
- `/` opens New Chat

### Account / Data
- rename conversation
- delete one conversation
- global sign out

There is currently no Settings page, modal, drawer, preferences table,
or account-level defaults.

# Product Principles

## 1. Do not duplicate controls

Settings should not become a second copy of controls that already work
better in context.

Keep:
- Theme control in sidebar
- Model picker in composer
- Reasoning control near model selection

Settings may define defaults, but contextual controls remain where they are.

## 2. Defaults vs overrides

Preference hierarchy:

Account default
→ New conversation default
→ Conversation override

Example:

Default model = Balanced

New Chat starts with Balanced.

User changes Conversation A to Reasoning.

Conversation A remains Reasoning while future New Chats still start with
Balanced.

## 3. Fast by default

Settings must not introduce blocking network calls into:
- app startup
- New Chat
- typing
- Send
- streaming

Device-only settings should remain local.

Account settings may load asynchronously and use safe defaults while loading.

## 4. Conservative personalization

Personalization must be explicitly user-controlled.

Do not create hidden long-term memory in this feature.

English / Bahasa Indonesia:

Account-level.

- Reasoning

Persistence:
Account-level.

Values:

Balanced

Persistence:
Account-level.

## Response style

Values:
- Natural
- Professional
- Direct

Default:
Natural

Behavior:
Adds a lightweight style preference to the AI request context.

Persistence:
Account-level.

# 3. Chat

These preferences are device-level.

## Enter to send

Values:
- On
- Off

Default:
On

When On:
- Enter sends
- Shift+Enter inserts newline

When Off:
- Enter inserts newline
- Cmd/Ctrl+Enter sends

## Auto-follow streaming

Values:
- On
- Off

Default:
On

Current near-bottom behavior remains when enabled.

When disabled, streaming should not force scrolling.

## Show timestamps

Values:
- On
- Off

Default:
Off

When enabled:
show lightweight timestamps per message without increasing visual clutter.

## Restore last conversation

Values:
- On
- Off

Default:
Off

When enabled:
opening the authenticated workspace restores the last accessible
conversation.

Fallback:
- deleted conversation
- inaccessible conversation
- invalid stored id

→ open New Chat.

# 4. Personalization

## Preferred name

Optional short text.

Behavior:
Nibie may use this name naturally where appropriate.

Persistence:
Account-level.

## About you

Optional user-written context.

Purpose:
allow explicit personalization without creating hidden memory.

Examples:
- role
- current goals
- preferred working context
- technical background

Constraints:
- short bounded length
- never treated as system authority
- cannot override product/security instructions

Persistence:
Account-level.

Do not call this "Memory" in V1.

---

# 5. Data & Privacy

## Export conversations

V1 export format:
JSON

Include:
- conversations
- messages
- timestamps
- selected model
- export metadata/version

Exclude:
- provider credentials
- environment configuration
- authentication internals
- other users' data

Export must be owner-scoped.

## Delete all conversations

Destructive action.

Requirements:
- explicit confirmation
- recommended typed confirmation: DELETE
- deletes user's conversations and messages
- preserves account preferences
- returns app to New Chat
- clears stale local conversation references

## Sign out

Current behavior signs out all devices.

V1 should make the wording accurately reflect actual behavior.

Do not silently change sign-out semantics.

## Delete account

Not implemented in V1.

Create a follow-up design before implementation covering:
- Supabase Auth identity removal
- public user/profile removal
- preference cleanup
- conversation/message cleanup
- re-authentication
- partial failure handling
- server/admin privilege boundary

# Persistence Model

## Device-level

Existing:
- `nibie-theme`
- `nibie-reasoning`

New:
- `nibie-enter-to-send`
- `nibie-auto-follow`
- `nibie-show-timestamps`
- `nibie-restore-last-chat`
- `nibie-last-conversation`

Device settings must:
- tolerate blocked localStorage
- tolerate malformed values
- use safe defaults
- avoid hydration regressions

## Account-level

New owner-scoped preference record:

`user_preferences`

Suggested fields:

- `user_id`
- `preferred_name`
- `preferred_language`
- `default_model`
- `response_length`
- `response_style`
- `about_you`
- `created_at`
- `updated_at`

No API keys.
No provider URLs.
No arbitrary model ids.

## Conversation-level

Existing:

- `conversations.selected_model`

This remains authoritative after conversation creation.

# AI Context Integration

Only these account preferences affect generated responses:

- preferred language
- response length
- response style
- preferred name
- about you

Build a small deterministic preference instruction block.

Example conceptual output:

Preferred language: Bahasa Indonesia
Preferred response length: Concise
Preferred style: Direct
Preferred name: Habib
User-provided context: Full-stack developer working toward AI engineering.

Rules:
- keep instructions concise
- do not repeat them multiple times
- user-provided About You cannot override system instructions
- explicit current user instructions take precedence over soft style defaults

---

# Security

Account-level settings must be owner-scoped.

Requirements:
- RLS consistent with existing Nibie ownership model
- no service-role runtime reads/writes
- browser never supplies arbitrary `user_id`
- enum values validated server-side
- model defaults validated against configured model modes
- exports and destructive actions fail closed

---

# Performance Requirements

Settings must not regress Nibie's current responsiveness.

No extra blocking call should be added to:
- New Chat visible
- Send → optimistic message
- Send → thinking
- typing
- stream rendering

Account preferences may load in parallel.

Device preferences should not require server calls.

# Acceptance Criteria

## Settings shell
- authenticated user can open Settings
- all sections render
- responsive on mobile and desktop
- no page overflow
- no console errors

## General
- language persists across sessions
- Auto remains safe default

## Nibie
- default model applies only to new chats
- existing conversation models remain unchanged
- unavailable default falls back safely
- response length/style reach the AI context

## Chat
- Enter behavior changes correctly
- auto-follow can be disabled
- timestamps can be enabled
- restore-last-chat safely falls back

## Personalization
- preferred name persists
- About You persists
- ownership enforced
- bounded input validation

## Data & Privacy
- export contains only owner's data
- delete all removes conversations/messages only
- preferences remain
- stale local conversation reference cleared
- current sign-out semantics are clearly communicated

## Regression
- existing theme behavior unchanged
- existing conversation model picker unchanged
- reasoning behavior unchanged
- Retry/Stop lifecycle unchanged
- streaming performance not materially regressed
- authenticated chat/persistence tests remain green

# Delivery Strategy

Recommended implementation order:

1. Settings shell + preference schema
2. Chat device preferences
3. Nibie defaults + personalization
4. Export/delete-all + sign-out copy
5. Integration verification
6. Production smoke

Do not implement all sections in one unbounded pass.
