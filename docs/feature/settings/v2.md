# Settings V2

Settings opens from the sidebar account area. Desktop uses an 800px modal with a left navigation and independently scrolling content. At 640px and below, it fills the viewport and uses a compact, two-column section disclosure. The seven sections are the complete navigation; there is no search, Connections page, or placeholder billing flow.

| Section | Controls and scope |
| --- | --- |
| General | Dark / Light / System on this device; preferred language on the account |
| AI & Models | Configured Fast / Balanced / High default, response depth, response style on the account |
| Chat | Enter to send, auto-follow, timestamps, restore last conversation on this device |
| Personalization | Preferred name and About you on the account; existing email displayed read-only |
| Memory & Context | Existing recall toggle, paged saved memories, explicit edit/save, forget, delete |
| Usage & Plan | Existing Free allowance, actual remaining/used credits and reset timestamp |
| Data & Privacy | Export JSON, exact DELETE confirmation, global sign-out, account deletion availability |

## Persistence and inheritance

`lib/preferences/store.ts` and `app/actions/preferences.ts` remain the only account preference store and actions. The cookie-authenticated public Supabase client derives the owner; existing RLS and validation apply. No schema or migration changes are needed. Existing values (`responseLength: balanced`, `defaultModel: reasoning`) are retained beneath the Default and High labels.

The account default selects the model for a new general chat or Room thread. Existing conversations retain `selected_model`; composer overrides affect only that conversation. Only configured modes are offered. An unavailable stored default is retained, with the existing available-mode fallback explained in Settings. No provider routing, reasoning effort, output/token limit, credit pricing, spend guard, context assembly, or send/stream logic changes.

Theme keeps `nibie-theme`. Chat keeps `nibie-enter-to-send`, `nibie-auto-follow`, `nibie-show-timestamps`, and `nibie-restore-last-chat`; malformed/unavailable storage still uses the existing safe defaults. No new preferences or storage keys are introduced.

Preferred name and About you drafts stay in the dialog while sections change. Escape, Close and outside clicks ask before discarding unsaved text; Keep editing restores focus and retains both drafts. Only a successful save clears the submitted draft.

Choices save when selected. Personalization text and memory edits use explicit Save buttons. Account writes show Saving / Saved or an error; a rejected write retains the previous saved preference and the typed text for retry. Failed account loading disables account edits until a successful retry so fallback defaults cannot overwrite existing preferences. Theme and chat remain usable as device controls. Preview account edits last for that visit and never write to Supabase.

## Memory, usage, and privacy

Memory remains opt-in via the existing recall flag. Disabling it prevents saving/retrieval and does not delete saved facts, conversation history, or Room context. Memory lists include inactive entries, preserve pagination, and allow retry after a failed load. Forget marks inactive; Delete permanently removes that entry. These explicit actions retain the existing owner-scoped server contracts.

Usage loads only when Usage & Plan is visited, using authenticated `/api/usage` with no-store caching. The display validates the returned balances against the current policy allowance and formats the reset with its time zone. A failed or invalid response shows a retry, never an invented balance. Free-plan copy describes current availability; there are no upgrade buttons.

Export retains the existing versioned JSON endpoint and download. Deleting all conversations still requires exact DELETE plus an explicit click and remains blocked during a response. Account/preferences remain; account deletion has explanatory text and no fake action. Rejected deletion releases the pending UI state without removing the confirmation phrase. No service-role credentials, provider identifiers, or configuration secrets are exposed.

## Accessibility and review

The native modal makes the background inert, contains focus, requests closing on Escape or an outside click, locks background scrolling, and restores the connected opener (or the mobile menu button when the sidebar has unmounted). Desktop tabs use a roving tab stop with Arrow Up/Down and Home/End. Choice radios support arrow keys and Home/End. Pending saves mark them aria-disabled and block further mutations without removing keyboard focus; navigation resumes after completion. Mobile uses a labeled disclosure button and native navigation buttons. Tab, arrow keys and Home/End navigate the expanded list; selection returns focus to the trigger. Escape first collapses the picker. Controls have labels, visible focus, and 44px tap targets. Status and errors remain in the footer; content and long memory/privacy pages scroll within the dialog.

`tests/e2e/settings-v2.spec.ts` exercises all sections at 320, 390, 768, 1024, and 1440px, keyboard/focus, themes, device persistence and unavailable storage. Existing Settings, chat preferences, default inheritance, usage, stream/Stop/recovery suites remain applicable. Authenticated Settings tests use dedicated credentials; local review provisions disposable accounts and makes no paid provider calls. The DB/RLS suite independently verifies preference, memory, export and deletion isolation.

The manual Preview Smoke workflow accepts `suite: settings`, or run `npm run test:qa:preview -- --settings`. This suite verifies signed-in drafts, two delayed keyboard saves with focus retention, and all sections at 320/390px in both themes. It restores the original response depth and blocks chat endpoints. The harness still requires dedicated QA credentials, a READY immutable Preview matching Git HEAD, and Deployment Protection access. Local narrow-desktop Chromium checks do not verify physical mobile devices or VoiceOver/TalkBack; those remain a separate manual check.

Desktop/mobile dark/light captures are in [screenshots](screenshots/README.md). The existing AI quality CI gate now also runs the Settings, responsive, chat-preference and usage browser fixtures without provider credentials.
